<objective>
Give the runtime one typed door to the vendor REST API: four operations, four predicates, one abort discipline, and no way to reach anything else.

Purpose: `SYNC-01` requires typed operations for inventory and snapshots, for Gemini commands, and for temporary AWS IoT credentials, and requires that the excluded account-management routes stay unused. `D-06` fixes the transport as the built-in `fetch` behind a small typed wrapper owning base URL, authorization, timeouts, and redacted error reporting, so there is no HTTP dependency to review. `D-20` requires the boundary to produce a validated-shape record, not a decoded one, and typed linting makes an unchecked parse unusable anyway.

Output: a client with four named routes, hand-written predicates at every boundary, and a deadline on every request.
</objective>

export interface ApiConnectivity { connected: boolean; timestamp: number; }
export interface ApiDevice {
  deviceId: string;
  deviceTypeId: string;
  name: string;
  serialNumber: string;
  connectivity: ApiConnectivity;
  data: Readonly<Record<string, unknown>>;
}
export interface AwsCredentials {
  AccessKeyId: string;
  SecretAccessKey: string;
  SessionToken: string;
  Expiration: string;   // ISO-8601
}
export interface AwsCredentialsResponse {
  endpoint: string;
  clientId: string;
  credentials: AwsCredentials;
}
export interface DeviceCommand { desiredData: Readonly<Record<string, unknown>>; }
export interface CommandResult { success: boolean; }

export function isApiDevice(value: unknown): value is ApiDevice;
export function isApiDeviceList(value: unknown): value is ApiDevice[];
export function isAwsCredentialsResponse(value: unknown): value is AwsCredentialsResponse;
export function isCommandResult(value: unknown): value is CommandResult;

// src/cloud/api.ts after this plan
export const COMMAND_DEADLINE_MS = 2500;
export const ROUTES = {
  devices: 'GET /devices',
  device: 'GET /devices/{deviceId}',
  command: 'PUT /devices/{deviceId}/data',
  awsCredentials: 'GET /credentials/aws',
} as const;

export interface CloudApiOptions {
  baseUrl: string;
  auth: AuthClient;
  requestTimeoutMs: number;
  log: Logging;
}
export interface CloudApi {
  devices(signal: AbortSignal): Promise<readonly ApiDevice[]>;
  device(deviceId: string, signal: AbortSignal): Promise<ApiDevice>;
  awsCredentials(signal: AbortSignal): Promise<AwsCredentialsResponse>;
  sendCommand(deviceId: string, command: DeviceCommand, signal: AbortSignal): Promise<CommandResult>;
}
export function createCloudApi(options: CloudApiOptions): CloudApi;

Vendor REST contract (`.planning/intel/constraints.md` section 4 and section 5):

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/devices` | Discover devices and get snapshots |
| `GET` | `/devices/{deviceId}` | Get one device and its shadow snapshot |
| `PUT` | `/devices/{deviceId}/data` | Send a family-specific device command |
| `GET` | `/credentials/aws` | Get the AWS IoT endpoint, client ID, and temporary credentials |

The vendor also defines account, device-management, firmware, location, rule, and contact route
families. This version uses none of them; see `01-COVERAGE.md` for the recorded decision per family.

A command body is `{ "desiredData": { ... } }` and a successful command returns HTTP 200 with
`{ "success": true }`. An unauthenticated request returns HTTP 403 with a token-missing error.
The temporary credentials expire after approximately one hour and the client ID changes with each
credential response.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| vendor REST API → plugin | Untrusted JSON crosses here and becomes canonical safety state. |
| plugin → vendor REST API | The bearer token crosses here on every request and must not appear anywhere else. |
| plugin → error objects and logs | An error constructed from a response is a common secret-leak path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-27 | Tampering | response parsing | high | mitigate | Every body is typed `unknown` and narrowed by a hand-written predicate before it leaves the client; a rejected shape raises `CloudRequestError` rather than admitting a plausible but incorrect record. No assertion syntax exists in the module. |
| T-01-28 | Information disclosure | `CloudRequestError` contents | high | mitigate | The error carries the numeric status and a route label drawn from `ROUTES`, never the constructed URL, the response body, or any header value. |
| T-01-29 | Elevation of privilege | reachable route surface | medium | mitigate | `ROUTES` is a closed `as const` object and a test asserts its exact value set, so the excluded account, device-management, firmware, location, rule, and contact families cannot be reached without failing the suite. `01-COVERAGE.md` records the decision for each family. |
| T-01-30 | Denial of service | request lifetime | medium | mitigate | Every request composes the root signal with a per-request deadline, so no request outlives a shutdown and none hangs indefinitely. The command path uses the shorter 2500-millisecond deadline. |
| T-01-31 | Spoofing | opaque device identifier in a path | medium | mitigate | The identifier is URL-encoded before it becomes a path segment and is never split, parsed, or logged; it is the immutable accessory identity seed and a user-visible leak of it is forbidden. |
| T-01-32 | Tampering | automatic command retry | medium | mitigate | `sendCommand` performs exactly one attempt and never retries automatically; a potentially delivered command must not be re-sent. The retry policy elsewhere in this phase covers read paths only. |

## Flagged Planner Assumptions

rules leave `unresolved`. It is surfaced here rather than dropped:

- **SYNC-01, category `unclassified`.** The probe could not classify the requirement. The planner's
  reading is that the uncharted edge is the definition of "without using excluded account-management
  routes": the requirement names a negative surface, and a negative surface cannot be proven by a

  structurally with the `ROUTES` `as const` object plus an exact-set assertion, and records the
  per-family decision in `01-COVERAGE.md`. The residual assumption is that no future code path builds
  a vendor URL outside this module; nothing mechanically prevents that in this phase.
