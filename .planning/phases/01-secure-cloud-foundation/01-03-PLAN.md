export interface DeviceSnapshot {
  identity: DeviceIdentity;
  connectivity: ApiConnectivity;
  data: Readonly<Record<string, unknown>>;
  metadata: Readonly<Record<string, unknown>>;
  shadowVersion: number | undefined;
  deviceTimestamp: number | undefined;
  receivedAt: number;
}
export interface ReportedPatch {
  data: Readonly<Record<string, unknown>> | undefined;
  state: Readonly<Record<string, unknown>> | undefined;
  version: number | undefined;
}
export type DeviceSnapshotListener = (
  next: DeviceSnapshot,
  previous: DeviceSnapshot | undefined,
  changedKeys: readonly string[],
) => void;
export interface DeviceStateStore {
  snapshot(deviceId: string): DeviceSnapshot | undefined;
  deviceIds(): readonly string[];
  applyDiscovery(device: ApiDevice): DeviceSnapshot;
  applyReportedPatch(deviceId: string, patch: ReportedPatch): DeviceSnapshot | undefined;
  subscribe(deviceId: string, listener: DeviceSnapshotListener): () => void;
}

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| vendor shadow payload → state store | Untrusted partial documents merge into the record every safety decision later reads. |
| state store → subscribers | The notification contract decides what downstream phases believe changed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-10 | Tampering | `applyReportedPatch` merge path | high | mitigate | `ReportedPatch` carries no member able to hold requested state, so a `desired` section has nowhere to land; the shape is the control, not a convention. Merge is key by key over the previous record so an omitted field is preserved rather than cleared. |
| T-01-11 | Tampering | shadow message ordering | high | mitigate | A per-device `shadowVersion` watermark discards any patch whose version is not greater than the version already applied, so a replayed or reordered message cannot overwrite newer state. |
| T-01-12 | Tampering | snapshot mutability | medium | mitigate | Snapshots and their nested `data` and `metadata` records are frozen before return, so a consumer cannot edit canonical safety state in place. |
| T-01-13 | Denial of service | subscriber notification | medium | mitigate | Listener invocation is isolated: a raising listener neither stops the remaining listeners nor propagates out of the reducer, which keeps the Homebridge process free of unhandled exceptions. |
| T-01-14 | Information disclosure | listener failure logging | low | mitigate | The failure log carries a fixed message and no listener detail and no snapshot content. |
</threat_model>

## Flagged Planner Assumptions

The deterministic edge probe returned one `unclassified` row for `SYNC-02` that the auto-resolution
rules leave `unresolved`. It is surfaced here rather than dropped:

- **SYNC-02, category `unclassified`.** The probe could not classify the requirement, so no edge
  category was proposed. The planner's reading is that the load-bearing uncharted edge is the
  interaction between a partial merge and a family-validation failure: what the store does when a
  merged record stops validating. Phase 1 does not run family validation — the intel's store rule 7
  places it after each merge and the adapter arrives in the next phase — so this edge is genuinely
  outside this phase's scope and is recorded here for the next phase's spec rather than resolved with
  a backstop check.
