## Decisions Made

- **The account struct's silence member is the constant `true`, and the runtime test file names it.** `ACCOUNT_DECLINES_TO_VOUCH` replaced fourteen `shadowSilent: false` literals in `test/runtime/accountRuntime.test.ts` — eighteen sites carried that literal, and four of them are per-device assertions that now read the map and keep a real `false`. Flipping the remaining fourteen to a bare `true` would have left fourteen assertions that look like measurements of a silence and are readings of a constant — the anti-pattern this phase exists to remove, reintroduced in the file that reports on it. The cases that are genuinely about silence read `monitoringByDevice` instead, through a `silenceOf()` helper whose comment says why.
- **The halt and the shutdown push through `pushMonitoringTrust()`.** Both need the account struct and the map, and neither may write a live-reporting outcome or move the latch, because neither observed a live path. Reusing `reportMonitoringHealth()` there would have written a per-device failure for every pump on every shutdown.
- **The per-device failure-log kind carries the `deviceId` inside the kind string, not only inside the sentence.** `FailureLog` rate-limits per kind, so this is what buys each pump an independent cadence, and it makes the recovery line — built as `${kind} recovered.` — name the controller too.
- **`test/runtime/monitoringHealth.test.ts` converts to `silentDevices()` rather than to any aggregate.** Thirteen `trustNow()` assertions changed — ten of them direct reads of its silence member, three whole-struct or key-shape assertions — and each became a read of the device list. Writing `silentDevices().length > 0` in a test would have been the flatten expressed at the test tier, which the plan's prohibition covers "at any tier".
