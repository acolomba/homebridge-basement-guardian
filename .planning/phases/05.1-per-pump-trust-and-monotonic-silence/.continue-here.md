## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| A branch forked from `origin/main` | `execute-phase`'s `handle_branching` and the worktree harness both fork from `origin/HEAD`. **Measured on 2026-09-03: `origin/main` is 552 commits behind, and five of the six files this phase edits do not exist there** — `monitoringHealth.ts`, `clock.ts`, `basementGuardian.ts`, `test/platform.test.ts` and `features/support/world.ts` are all absent; only `platform.ts` is present. An executor on such a base has nothing to edit, and may create the files from scratch instead. | blocking | Stay on `features/phase-05-degraded-operation-and-recovery`. Ruled by the maintainer on 2026-09-03. Before accepting any branch the tooling proposes, run `git cat-file -e origin/main:<path>` on the files the plan edits and confirm they exist on its base. |
| Executor dispatch blocked by the isolation guard | `dispatch-isolation` reports the host capability (`harness-worktree`) while `worktree base-check` returns `shouldDegrade: true`, because a harness worktree forks from `origin/HEAD` — the same absent-source base as above. A mismatch between the sentinel and the dispatch makes the guard deny with exit 2, and the task does not run at all. | blocking | Force before **every** dispatch: `gsd-tools query dispatch-isolation --raw --force-isolation none`, then verify by **reading** `.gsd/dispatch-isolation-sentinel.json`. Never verify by re-querying — a bare query re-persists the capability and undoes the force. |
| A gate that cannot fail because of how it is piped | `pipefail` is **off** in this shell, so `npm run test:x \| grep y` returns *grep's* status and npm's failure is discarded. Proven: `(exit 7) \| grep x` returns 1. A Phase 5 plan shipped with five such gates — a red suite would have reported success. Seen again on 2026-09-03: a planner's commit reported success and did not land, hidden by `\| tail -3`. | blocking | Capture and assert both: `O=$(npm run test:unit 2>&1); R=$?; test $R -eq 0 && printf '%s\n' "$O" \| grep -qE '^ℹ fail 0$'`. Never pipe a suite command into a filter inside a `<verify>` block. After every commit, verify by content with `git show --name-only --format="" HEAD`. |
| A check that passes because the thing it rests on already sits at the value the defect produces | Phase 05's defining defect, seen at four layers. This phase has already met it four more times: research falsified four premises in `05.1-CONTEXT.md`, pattern mapping falsified two, the checker falsified one the planner asserted, and the planner falsified one the orchestrator asserted — the "empty map preserves every expectation" default, which would have broken `test/platform.test.ts:1290` on the one case it was meant to protect. | blocking | `05.1-VALIDATION.md` names the discriminating mutation for all 15 rows and is binding. Apply the mutation, watch the named test fail, revert, confirm green, and **record which test failed on what line**. Before trusting a new assertion, ask whether its expected value is already what the field holds. A mutation that fails nothing is a finding to report, not a failure to hide. |
| A false red from concurrent builds | Every suite command rebuilds the shared `dist-test/` tree, and a second session may share this working tree. Measured: a solo run gave `1385 / fail 0`, a concurrent one gave `pass 1383 / fail 2`. | advisory | Run one suite at a time — which is why all seven plans are separate waves. If a gate goes red, **re-run it alone before believing it**, and say in the SUMMARY if you had to. |
