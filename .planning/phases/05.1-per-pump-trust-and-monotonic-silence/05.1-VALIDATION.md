# Phase 05.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
>
> **Binding, in the sense `05-VALIDATION.md` is binding.** Every row names the mutation that
> must fail it. A row whose named mutation still passes is not evidence. Apply the mutation,
> run the named command, **record which test failed and on what line**, revert, confirm green.
> A mutation that fails nothing is a finding to write down, not a failure to hide — say where
> the behaviour is pinned instead, as ledger entries 21 and 26 do.

## Sampling Rate

- **After every task commit:** `npm run test:unit`, in the capture-both form below.
- **After every plan wave:** `npm test`, **run alone** — a concurrent run has been measured
  producing false failures (`1385 / fail 0` solo versus `pass 1383 / fail 2` concurrent).
- **Before `/gsd-verify-work`:** `npm test` green **plus** `npm run test:coverage:all` at
  100/100/100 **plus** `npm run fallow`.
- **Max feedback latency:** ~25 seconds (`npm run test:unit`).

### The verify form, every time

`pipefail` is **off** in this shell, so `npm test | grep x` returns *grep's* status and npm's
failure is discarded. Proven: `(exit 7) | grep x` returns 1. Capture and assert both:

```bash
O=$(npm test 2>&1); R=$?; test $R -eq 0 && printf '%s\n' "$O" | grep -qE '^ℹ fail 0$' && printf '%s\n' "$O" | grep -qE '^[0-9]+ scenarios \([0-9]+ passed\)$'
```

**Never** pipe a suite command directly into a filter inside a `<verify>` block.

**One result beyond what the checkpoint asked for, and the most useful of the session.** The anchor
file was copied before a deliberate restart and compared after it: **the stored anchor was byte-identical,
2026-09-04T19:12:41.078Z before and after.** That is plan 05.1-05's central rule observed on real
hardware rather than argued — `admitDevice` records an anchor only when the store holds none, so a
restart does not hand a device a fresh arrival. The unit and Cucumber tiers pin the same rule against
a stale anchor; this run shows the live path writing, restoring and declining to overwrite one.

**What this session did not cover.** No pump cycle, fault, power event, controller-link drop or
reconnect occurred, so every degradation path stayed unexercised end to end. The container ran
Node v24.20.0, which is a runtime smoke result for the shipped plugin and **not** a Node 24 suite
result; none is claimed.

**Recorded limit (D-10):** the vendor account has exactly one Gemini. **No real multi-device
evidence exists and none can be obtained.** Every two-pump claim in this phase rests on the
Cucumber harness and on the mutations above, and must say so. Do not write a record that reads
cleaner than the measurement.

**Recorded limit (evidence for the clock):** the monotonic finding was falsified in both
directions with a Linux time namespace on the two installed Node runtimes. **Node 24 is not
installed and no Node 24 result may be claimed.** The suspend consequence is cited from
`man 2 clock_gettime`, not observed — this host has no accumulated suspend time.
