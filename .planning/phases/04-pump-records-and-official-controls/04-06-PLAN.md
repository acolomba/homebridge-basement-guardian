```
Activity History (.planning/intel/constraints.md:391 and https://support.apple.com/en-gb/105011)
  - owned by the controller, up to 30 days for eligible accessories including contact sensors
  - requires a supported home hub and the current Home architecture
  - the plugin cannot set retention and cannot backfill missed events

Tile visibility (.planning/intel/constraints.md:380-395)
  - a room holding only sensors does not render in the main Home view; it is still selectable
    from the room list, and the Security summary shows only currently triggered sensors
  - the Self-Test switch is what makes the room visible at all
  - a battery service is not a tile: it surfaces in accessory details and the battery list
  - vendor-defined services carry identifiers outside Apple's assigned base namespace
    `-0000-1000-8000-0026BB765291`, which is why Apple Home draws no tile for them

Timing (.planning/intel/constraints.md and 04-CONTEXT.md D-12)
  - a backup pump run lasts roughly 7 to 15 seconds
  - the default REST poll is about every 15 minutes
  - the observed self-test duration is about 16 seconds
  - therefore live delivery, not polling, is what makes counting a primary run possible

Controls (.planning/intel/constraints.md:107-113, 535-541, 546-554)
  - the official client permits a self-test while equipment faults are present and disables the
    command only when the system is offline
  - the system has no cancel command; the plugin refuses an off write during a test
  - the official client disables mute when the system is offline or already muted, and exposes
    no duration selector and no unmute command
  - a test started from the vendor application or an automatic schedule updates the same switch
  - hardware validation must still confirm mute acknowledgement, reported-state timing, actual
    duration, and failure behaviour
```
