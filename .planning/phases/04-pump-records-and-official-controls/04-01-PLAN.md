architectural dead end surfaces after one commit rather than after ten. The fidelity gate is part of
the same plan because a green scenario over a fake this phase authored is exactly the evidence
`.continue-here.md` warns is worthless.

scopes, and the fidelity test that keeps the harness honest.

## Plan size, and why the tracer is not split

This plan is 23 files and its calibrated projection is 1.30x the smart-zone budget
(`estimate-check --calibrated`: 130000 against 100000, `confidence: low`, `sample_count: 0`). The
projection is uncalibrated for this project, so weigh the file count over the token figure. The size
is accepted on one argument, which was checked rather than asserted: extending `TrustScope` forces
`ScopedDomainState`, `gemini.decode`, the three `TELEMETRY_CHECKS` rows and `TRUST_SCOPES` in one
edit, or the tree does not typecheck. There is no smaller edit that leaves the repository green.

A second argument was made for this plan's size and it was wrong, so it is corrected here rather than
left standing. Shipping the Switch without the off-write refusal would **not** send
`{ test_running: false }` to a real pump: without the binder there is no `onSet` handler at all, so a
press stores a value locally and sends nothing. The real hazard is milder — a Switch that looks
writable and silently does nothing. It is still worth avoiding, but it is not the safety argument the
earlier wording claimed.

The suggested split is declined. Making the fidelity task its own wave-1 plan with the tracer behind
it inverts the actual dependency: the fidelity test compares the fake's write path against real HAP,
and the fake has no write path until the tracer creates it. Splitting the other way — the fidelity
task into a new wave-2 plan — would renumber every later plan and shift four waves to buy a margin an
uncalibrated estimate cannot measure. Both tasks stay here, the tracer first.

Feedback latency is bought back by sampling rather than by splitting: each task runs its narrow gate
first — the focused coverage pair, or the `--name`-filtered scenario run — and the whole suite after.
The sample does not replace the whole suite, which stays as the wave-end gate.
