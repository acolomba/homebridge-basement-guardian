<objective>
Retire the build-configuration exemptions this phase's production consumers made stale, and write the
administrator-facing explanations the phase's decisions require: what an inactive scope means, what
removing an adapter costs, and which published numbers are estimates rather than measurements.

Purpose: `src/accessories/services.ts` was declaration-only and carried an `ignoreFindings` entry that
said so; it now carries runtime values that `src/config.ts` consumes, so the entry is stale and the
module should stand on its own against the gate. `src/device/health.ts` may or may not have earned the
same, which is why this plan measures rather than assumes — a speculative removal fails
`npm run fallow` and, because exactly one plan may edit this file, would serialise a wave for nothing.
The documentation half closes the obligations three decisions created: `D-05` requires the
inactive-scope behaviour to be documented because it is a visible departure from what plugins usually
do, `D-017` and the runtime-state review require `ignoredFaults` to be described as destructive, and
the estimate labelling keeps a band and a provisional ladder from reading as measurements.
Output: a smaller `ignoreFindings` list with every remaining entry justified, and a README and
changelog an administrator can act on.
</objective>
