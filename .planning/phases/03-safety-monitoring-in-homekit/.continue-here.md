## Product changes shipped 2026-08-31

Both closed checks found real defects rather than confirming expectations.

- **Service naming** (`39560ac`). Apple Home listed the sensors as "Contact Sensor 1"
  through "Contact Sensor 8". Every published service now seeds `ConfiguredName` from
  `RowDefinition.displayName`. Verified end to end: all 15 services carry it in the
  live HAP database, Apple Home displays them, and a user rename survived three
  republish cycles through both publish paths.
  **`ConfiguredName` is paired-write.** The plugin seeds it only when absent. Writing
  it on every publish would revert a user's rename, and `Characteristic.serialize`
  persists the value, so that would destroy user data rather than flicker a label.
  Note Apple's own metadata does **not** declare `ConfiguredName` on `ContactSensor`
  or `LeakSensor`; it works anyway, via the declare-before-push guard.
- **Settings form** (`cdb183d`, `c268b34`). Raw slugs became seven alphabetised,
  human-named checkboxes. `items.enum` is what selects the checkbox widget — a test
  asserts its existence and says why. Removing it drops the control to per-item
  dropdowns with a `None` option.

### Rebuilding the UAT harness

`dev/` is committed and works, but `dev/README.md` overstates what it can do. See
`.planning/todos/pending/2026-08-31-state-the-harness-mdns-prerequisite.md`, which
carries the full findings. The essentials:

- **Pairing needs host multicast.** On this VM, `_hap._tcp` sees 0 responders from
  floyd while another LAN machine sees 26.
- **The sequence that works here:** `sudo ip link set ens3 promisc on` **first**, then
  restart Homebridge. Order matters — the bridge announces at startup.
- **`bridge.advertiser: "avahi"`** in the container's `config.json`. `dev/hb` does not
  write it, and HAP's own mDNS stack does not reach the LAN under `network_mode: host`.
- **firewalld** blocks `51826/tcp` and `mdns` by default on Fedora Server.
- **The Config UI binds `127.0.0.1` only** — `ssh -L 8581:127.0.0.1:8581`.
- **A stale pairing blocks re-pairing.** A Home app "Remove Accessory" does not reach
  an unreachable bridge: it still lists a paired client and advertises `sf=0`. Clear
  `pairedClients` and `pairedClientsPermission` in
  `dev/homebridge/persist/AccessoryInfo.*.json` with the container stopped. Far lighter
  than `./dev/hb reset`.
- **Do not try macvlan.** It was attempted and failed — the container could not ARP its
  gateway, because a KVM guest will not accept frames for a second MAC.

The water-level override is not committed anywhere and must be rebuilt. It patches
compiled `dist/accessories/basementGuardian.js`, never `src/`, and must intercept
`update()` — where a snapshot is **read** — never the state store's `freeze()`, which
is where it is **persisted**. A 2026-08-30 version placed it in `freeze()`; forced
values entered canonical state and the scope stayed degraded permanently.

**Any commit touching `src/` erases a `dist/` scaffold**, because `pre-commit` runs
`npm fallow`, whose `prefallow` runs `npm run build` (`rimraf ./dist`). Expect it and
re-inject; never skip the hook.
