<objective>
Prove the phase's safety behaviours end to end against the real plugin and the fake vendor cloud, and
add the fourth layer of the immediacy gate: a check that no module in the accessories tier can reach
for deferred execution at all.

Purpose: the unit suites prove each module in isolation. These scenarios prove the assembled plugin —
fake Auth0, fake REST, fake shadow broker, real runtime, real platform, real accessory, the HAP
stand-in — turns a vendor field change into a published HomeKit characteristic change. The static
gate closes the remaining hole in the immediacy evidence: the injected port and the global spies
cannot see a deferral written through `node:timers/promises`, which three existing modules already
import, so a check that no accessories module imports it at all names the failure precisely and
cheaply.
Output: `features/safetyMonitoring.feature` covering every transition, the `Then`-steps that read
published state back, and a static gate with a proven negative control.
</objective>

From features/support/world.ts (the harness config the new Given step feeds):
```typescript
  /** The account settings the scenario configures the platform with. */
  settings: Record<string, unknown> = {};
```
`settings` reaches only `loadPlatform()`. The harness `launch()` path builds its runtime config
directly, so a scenario-configured `ignoredFaults` needs its own world field that `launch()` reads
when it builds the `DiscoveryContext`.

Legal Gemini value domains, so every scenario field validates
(`.planning/intel/constraints.md` lines 246-249):
```
water_level          0, 1, 3, 7, 15, 31
battery_health       1, 2, 4, 8, 16, 32
hours_of_protection  1, 2, 4, 8
```
`features/shadowMerge.feature` deliberately uses values outside these domains, because its subject is
the canonical store rather than the accessory. Scenarios in this plan use legal values only, so the
family adapter validates and the accessory publishes.

Verified constraint behind the static gate (03-RESEARCH.md § "Pitfall 5"): spying
`globalThis.setTimeout` and then awaiting a `node:timers/promises` timer records zero calls on the
spy, so the global-spy layer cannot see that form of deferral.
