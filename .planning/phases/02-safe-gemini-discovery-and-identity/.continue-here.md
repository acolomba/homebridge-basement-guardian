## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Test encodes the defect | `features/shadowMerge.feature` asserted CR-01's empty-patch freshness bug as correct, and `test/runtime/accountRuntime.test.ts` did the same for CR-02's telemetry revert. Both passed. Fixing the code required amending the tests, which an executor can easily read as "don't break the suite". | blocking | When a gap plan closes a defect, it must name the test that encodes it and instruct the amendment explicitly. Verify each new assertion fails against the pre-fix build individually. |
| Flaky gate reported as green | `npm run check` exited 1 on one run in four (a step-definition race on the SYNC-04 scenario) while every wave report said "all gates green". The orchestrator's own runs happened to pass. | blocking | Before reporting a suite as green, run it at least 3 consecutive times. The Phase 1 fix is in place and verified 6/6, so a failure now is a real regression. |
| Stale facts inside plan text | Plans 01-07 and 01-08 both asserted "no local pre-commit hook fires on a `features/`-only commit", which stopped being true in Wave 1. Plan 01-07 also described 01-08 as "in this same wave" after it had already merged. | advisory | Brief every executor with corrections drawn from prior SUMMARYs, and tell it which claims in its own plan are stale. |
| Intra-wave `files_modified` overlap | 01-03 and 01-07 both modified `.fallowrc.json` in one wave, forcing serialization. The deeper hazard: this repo's dead-code gate forces *undeclared* edits to that file from any `src/**/*.ts` change, so overlap is not visible in `files_modified` alone. | advisory | Check pairwise file overlap before dispatching a wave, and treat shared config files as a serialization signal even when undeclared. |
| Worktree cleanup blocks on any deletion | `worktree.cleanup-wave` refuses any branch that deletes a file, with no opt-in (upstream #3003). Phase 1's template teardown was legitimate and fully declared. | advisory | Standing decision: merge when every deleted path appears in the plan's `files_modified`; halt and ask the user if anything undeclared is deleted. |
| `test:coverage:direct` needs two arguments | The npm script ends in `--test-coverage-include`, so a single argument becomes the include value and leaves `node --test` with no test glob. It then globs unbuilt `.ts` and fails on every file. Cost four executors time. | advisory | Pass BOTH the include value and the test path. Say so in every executor brief that mentions coverage. |

## Open Items Bearing On Phase 2

Surfaced by the Phase 1 security audit, recorded in `01-SECURITY.md` without a register row:

1. `src/persistence/accessoryContext.ts` declares `deviceId` while its own fileoverview promises
   the record holds no account identifier — and the vendor `deviceId` embeds one. Homebridge
   writes accessory context to disk in plaintext and includes it in backups. Nothing writes the
   record yet. The Identity constraint and the Privacy constraint collide here, and Phase 2
   establishes identity.
2. The token cache does contain the raw account email — not in metadata, but inside the stored
   `id_token`, whose JWT payload carries an `email` claim under the `openid profile email` scope.
   The comment in `src/cloud/auth.ts` claiming otherwise is inaccurate.
3. `deleteCachedToken` runs only on the 4xx refusal branch. An email fingerprint mismatch
   overwrites rather than deletes.
4. The SigV4 test's canonical form is hand-mirrored from the same spec reading as the signer, and
   the fake broker accepts every signature. Only a real handshake can falsify that reading.
5. `cucumber.json`'s `default` profile has no tag fence; a future `features/real-pump/**` would be
   picked up by the deterministic run. `"tags": "not @real"` would close it pre-emptively.
