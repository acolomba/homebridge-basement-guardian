<objective>
Unify `platform.ts`'s register-vs-update branch so a cached accessory is always found and updated by
its `deviceId`-derived UUID alone (`DEV-04`), and add vendor-rename adoption on top of that update
path so a vendor-side rename is applied only when it does not overwrite a user's own rename
(`DEV-06`, `D-030`).

Purpose: Plan 02-01's tracer only ever registered a brand-new accessory; this plan is the first to
exercise the "already cached" branch `configureAccessory` populates on every Homebridge restart, and
adds the one piece of `AccessoryContext` state (`lastVendorName`) that `DEV-06`'s adoption rule
needs. `src/persistence/accessoryContext.ts` was declaration-only since Phase 1; this plan is its
first real production writer.
Output: `platform.ts`'s update branch is complete for the every-poll, already-cached case;
`AccessoryContext` gains `lastVendorName`; the fileoverview's incorrect "holds no account identifier"
claim is corrected per the locked `deviceId`-is-non-sensitive decision.
</objective>

      while `accessory.context.lastVendorName` still advances to the new vendor name (so a future
