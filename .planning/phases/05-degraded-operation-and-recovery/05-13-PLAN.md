<objective>
Give the end-to-end suite the ability to describe a two-pump account, and use it: two scenarios that
prove the plugin publishes one accessory per system and observes each system apart from the other.

Purpose: `05-REVIEW-2.md` found four blockers, and three are interactions between plans that each
verified cleanly alone. `CR-01` is invisible to the whole suite for one reason -- **no scenario uses
more than one `deviceId`** -- so an account-wide clock standing in for a per-device fact cannot be
caught by any end-to-end assertion that exists. This plan removes that blindness as a deliverable in
its own right, before the plan that depends on it. An owner with two sump systems is an ordinary
owner, and until now nothing proved the plugin serves them.

Output: a named-accessory read, a named-device publish, two scenarios, and validation rows. No
production module changes.
</objective>

## Why the harness comes first, and alone

`05-REVIEW-2.md` reproduced `CR-01` by executing the built modules directly, outside both test tiers,
because neither tier could express it. The unit tier can be taught a second `deviceId` in an
afternoon; the end-to-end tier cannot, because three separate helpers each collapse the account to one
device and 96 scenarios rest on that collapse.

Landing the harness change and the `CR-01` behaviour change together would make the behaviour change
unprovable in the way this phase has already been caught out by twice: a scenario that goes green when
two things move at once cannot say which one it was measuring. So this plan lands the capability and
proves it on behaviour that is **already correct today** -- two pumps publish two accessories, and a
message for one does not move the other. Both scenarios must pass on unmodified production code. If
either fails, that is a new finding, and it is recorded rather than fixed here.

That also makes the next plan's evidence sharp: `05-14`'s scenario is written against a harness whose
two-device reads are already proven, so a red result there is about `CR-01` and nothing else.
