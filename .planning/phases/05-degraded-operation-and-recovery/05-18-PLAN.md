<objective>
Close the platform's three blind spots: an ordering claim the unit tier cannot see, a context literal
written three times, and a pass whose name promises more than it does.

Purpose: `05-REVIEW-2.md` WR-01, WR-07 and WR-08. The first is the one that matters most, and it is a

duplication that grew from a two-way one in this phase, on exactly the seam D-12 exists to protect.

that carries a trust report, and a count that would tell an operator the pass reached nothing is
discarded.

when it reaches nothing, and the validation rows.

## What WR-01 is really about

The finding is not that the ordering is wrong. It is right, and two Cucumber scenarios prove it. The
finding is that a comment claims a case pins something the case cannot observe, and a reader who
trusts the comment will move the loops and see green.

That is the same failure this whole round exists to close, one tier down: a criterion aimed at the
implementation rather than at what must be observable. The recording stand-in is a perfectly good
instrument for the claim it was built for -- every accessory hears the same answer -- and a poor one
for a claim about what lands on a characteristic, because it lands nothing on any characteristic.

So the fix is an instrument, not a rewrite: build a real accessory over the same restored accessory
the error push walks, so the two loops touch one set of services and an inverted order is observable
as a value where a status should be. The recording case stays, with its comment corrected to say what
it actually pins.
