<objective>
Make the one failure only the owner can fix reachable in the case owners actually hit, and tell the
accessory tier when the runtime has stopped.

Purpose: `05-VERIFICATION.md` CR-03 confirmed by probe that the halt flag is assigned in exactly one
place, inside `launchFailure`, reachable only from `launch()` and `relaunch()`. After
`startBackgroundWork()` has run, `runPoll`'s catch does not inspect the error type and
`refreshCredentials`'s catch swallows everything into a rotation failure, so no path sets it. An
owner who changes their vendor password while Homebridge is running gets `warn Device discovery
failed.` forever: no accessory goes unreadable, no authentication line is logged, and the poll loop
keeps waking against a locally halted auth client. The whole `D-10` presentation is reachable only
through a restart. All five credential tests in the repository reject the **first** inventory call,
which is why nothing caught it.

WR-07 is the same shape from the other end: `stop()` sets the stopped flag and pushes nothing, so
every accessory keeps `commandTransportReady: true` from the last successful poll and a press
arriving during shutdown is accepted by the local gate and turns into a vendor error — a HomeKit
failure naming the vendor for a refusal that was entirely local.

Output: one terminal branch every loop routes through, three loops that stop once it fires, a final
push from shutdown, and tests that reject something other than the first call.
</objective>
