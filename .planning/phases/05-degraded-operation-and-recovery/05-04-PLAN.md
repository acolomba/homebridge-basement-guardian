<objective>
Make a vendor refusal of the account credentials a persistent, user-actionable communication failure
that survives until the user acts — and first make the test harness capable of telling whether it
worked.

Purpose: `RES-04`'s last clause says only explicit credential rejection yields a persistent
communication failure requiring user action. `D-10` grants this a narrow, deliberate exception to a
locked Phase 3 decision, because credential rejection is unlike every other failure in the phase: it
never self-clears, and an automatic retry extends the vendor's thirty-day block rather than merely
failing. Research proved the mechanism reachable through the push path alone, so the exception costs
no read handler and does not reopen `D-09`.

A defect found while planning makes the harness work non-optional and puts it first:
`features/support/fakeHap.ts`'s `updateCharacteristic` clears the stored status and stores whatever
it is handed, including an error object, while the real `updateValue` short-circuits on an error and
returns before touching the value. Every assertion in this plan would run against a stand-in that
models the opposite of what production does.
Output: a faithful stand-in, the fidelity case that holds it faithful, the push, and the scenario.
</objective>

no test in this repository or in the pinned packages can answer. `D-10` records that a negative
finding reopens the decision. The human check on task 2 carries all three into the phase's
verification session, joining the open items in `04-UAT.md`.
