<objective>
Separate the two questions a reported shadow document answers -- did it observe the device, and did it
deliver telemetry -- so a document carrying only device metadata cannot take the readings away from
polling.

Purpose: `05-REVIEW-2.md` CR-03. `nextShadowVersion` already refuses to *establish* a watermark from a
document that observed nothing, and its own comment names the hazard exactly: a document carrying no
observation would take ownership from the poll on the strength of having seen nothing, freezing
telemetry at whatever the poll last wrote. The guard is one field short. `carriesObservation` answers
`data` **or** `state`, but ownership governs `data` alone -- `state` is device metadata, merged into
`snapshot.metadata` and read by nothing safety-relevant except `FirmwareRevision`. The plugin
subscribes to the topic that carries exactly the delta a device just reported, so a device updating
only its `state` section produces this patch in ordinary operation. It compounds: the same message
stamps the arrival clock, so the silence predicate never fires and nothing releases the lock. Proven
against the built store -- after a `state`-only document, a poll reporting a changed level still read
the old one. Every tile reads normal, fully vouched for, over data no transport delivered.

Output: a one-field guard, the store and runtime cases behind it, the harness step and scenario that
show it from a basement, and the validation rows.
</objective>

## The fix, and the one rejected

**Chosen -- split the question at the call, not at the predicate.** `carriesObservation` keeps its
meaning and its name: it answers whether the message said anything about the device, and `receivedAt`
keeps using it, because a metadata report *is* a report about the device. `nextShadowVersion` stops
taking `observed` and asks its own, narrower question directly:

```ts
function nextShadowVersion(previous: DeviceSnapshot, patch: ReportedPatch): number | undefined {
  if (patch.data === undefined && previous.shadowVersion === undefined) {
    return undefined;
  }

  return patch.version ?? previous.shadowVersion;
}
```

Two predicates, two questions, each read where it is answered. The existing comment already argues the
ordering-versus-ownership split; it gains the sentence that says which section ownership is about.

**Rejected -- narrow `carriesObservation` to `data` alone and leave both callers on it.** One line
shorter and wrong in the other direction. `receivedAt` would then stop moving on a metadata report, so
the snapshot's only freshness field would go stale while the device was demonstrably speaking, and a
reader diagnosing a stale-looking snapshot would find a device that had reported minutes ago. Worse
after plan 05-14: if the same narrowing ever reached the arrival stamp, a device reporting only
metadata would be called silent, its telemetry would be released, and a healthy pump would be marked
untrustworthy. A false silence is not a safe direction to fail in; it is a different wrong answer.
