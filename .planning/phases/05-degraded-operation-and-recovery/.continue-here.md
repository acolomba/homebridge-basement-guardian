## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| A check that rests on the defect's own value | A test, fixture, harness, gate or plan claim passes *because* the thing it depends on already sits at the value the defect produces. Seen **eleven times** this phase: `water_level: 2` outside the accepted domain so a sensor deactivated on field validation rather than silence; `world.ts` calling the marking function directly so deleting the real call site left all of Cucumber green; a static gate whose root resolved to `dist-test/` and walked zero TypeScript files; a coverage gate that answers a different question depending on argument order; four executors disproving premises their own plans asserted. | blocking | For every safety-bearing claim, apply the named mutation, watch the specific test fail, revert, confirm green — and record which test failed. `05-VALIDATION.md` names the mutation for each behaviour and is binding. Report honestly anything that fails nothing. |
| Per-plan verification cannot see between plans | Twelve plans each verified cleanly alone, and **three of the four outstanding blockers are interactions between them**. Mutation-testing a plan in isolation is structurally blind to a defect that lives between two correct plans. | blocking | Review the phase as one artifact after any multi-plan round, not as a series of fixes. That is what produced `05-REVIEW-2.md`. |
| A dimension nothing is looking at | The suite has **no multi-device coverage at all** — every scenario uses a single `deviceId`. CR-01 survived twelve rounds for that reason alone. The live dev container also has exactly one Gemini, so it cannot reproduce or refute it either. | blocking | Add multi-device scenarios as a deliverable in their own right. Never cite the dev container as validation for behaviour that needs a second device. |
| `gsd-tools query commit` reports success while committing nothing | Observed repeatedly in this repository. | advisory | `pre-commit run --files <paths>` → `git add <paths>` → plain `git commit` with **no pathspec** → verify with `git show --name-only --format="" HEAD`. Never `--no-verify`, never rebase. |

<blockers>
All four are false-normal paths, every one reproduced by executing built modules. Full detail and
transcripts in `05-REVIEW-2.md`.

- **CR-01 — a two-pump account can silently discard a flood.** Shadow silence is tracked
  account-wide (`monitoringHealth.ts:141` holds one `lastShadowMessageAt`) while telemetry ownership
  is per device, and `onReportedPatch` discards the `deviceId` it is handed
  (`accountRuntime.ts:613,639`). One pump's heartbeat re-stamps the account clock, so a permanently
  quiet pump never trips `shadowSilent`, is never released, and has every poll body discarded.
  Reproduced over 10 simulated hours: the poll reported `31` on all 40 polls, the store still read
  `3`, `Status Active` stayed `true`.
- **CR-02 — a control press after a credential refusal permanently un-marks both controls.** 05-12
  closed the message route; the write route is open. `refuseLocally` → `armClearingPush` →
  `clearRefusal` → `republish()` → `publishRow` ends in `publishValue(service, StatusActive, …)`, and
  a value push clears a stored status. Permanent, because a halted runtime never pushes again.
  `expire()` and `refuseOutcome()` leak identically. **The restored-accessory path does not leak,
  because it passes `nothingToRepublish` — that is the shape of the fix.**
- **CR-03 — a metadata-only shadow document steals telemetry ownership.** `carriesObservation`
  answers `data || state`, but ownership governs `data` alone.
- **CR-04 — `README.md:145` and `CHANGELOG.md:24` promise readings the code discards** for the ~30
  minutes before release; `test/runtime/accountRuntime.test.ts:987` pins the opposite deliberately.

**Two of the phase's own claims failed mutation and must be fixed:** `test/platform.test.ts:1248`
