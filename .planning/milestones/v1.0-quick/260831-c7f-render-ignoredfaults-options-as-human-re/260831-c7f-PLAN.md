<objective>
Replace the bare string enum behind `ignoredFaults` in `config.schema.json` with `oneOf`
entries carrying `title`/`enum` pairs, so the Homebridge Plugin Settings GUI offers the seven
removable notification sensors under their published HomeKit names instead of their
configuration slugs.

Purpose: an administrator reading the generated form currently sees `backup-pump-activated`
where their home shows `Backup Pump Activated`. The slug is the correct value to write into
`config.json`; it is the wrong thing to read in a picker. This closes the third deferred human
verification item recorded in `.planning/STATE.md` ("The `ignoredFaults` array renders
acceptably in the Homebridge Plugin Settings GUI under `strictValidation: true`").

Output: a labelled `ignoredFaults` option list in `config.schema.json`, plus the cases in
`test/configSchema.test.ts` that hold the label-to-slug mapping to the service catalogue.

**Scope note on "no existing test changes".** The task brief asked that every existing test
keep passing unchanged. One cannot: `test/configSchema.test.ts` currently asserts
`deepStrictEqual(ignoredFaults.items, { type: 'string', enum: [ ...seven slugs... ] })`, which
is an assertion about the *representation* this plan deliberately changes. Its *invariant* --
exactly those seven slugs, in that order, and no other value -- is preserved verbatim in the
rewritten case. Everything that tests behaviour is untouched: `src/config.ts` is not edited,
and `test/config.test.ts`, `test/platform.test.ts`, `test/settings.test.ts`, and every Cucumber
feature pass with no change.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| administrator -> Config UI form -> `config.json` | The form is a convenience writer; the file it produces is untrusted input to the plugin. |
| hand-edited `config.json` -> `validateConfig` | The form can be bypassed entirely, so the runtime re-checks every field. |
| repository `config.schema.json` -> homebridge-config-ui-x | A schema the UI refuses degrades the administrator's only graphical route to the settings. |
