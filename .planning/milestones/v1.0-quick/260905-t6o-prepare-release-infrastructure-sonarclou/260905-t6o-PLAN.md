<background>
**Coverage path mismatch (verified by dry-running the pipeline during planning).** This repo compiles
TypeScript to `dist-test/` via `tsc` before running `node --test` (see `build:test`, `test:unit` in
`package.json`). Running node:test's `--experimental-test-coverage` with the `lcov` reporter against
that compiled output produces `SF:dist-test/src/settings.js`-style paths -- the compiled JS, not the
original TypeScript. `sonar-project.properties` will declare `sonar.sources=src`, so an lcov file with
`dist-test/src/*.js` paths sits outside Sonar's source tree and Sonar silently reports 0% coverage
(no error, no warning). `tsconfig.json` already sets `sourceMap: true` and it is inherited by
`tsconfig.test.json`, so a straightforward path/extension rewrite -- `dist-test/src/foo.js` ->
`src/foo.ts` -- fixes this cleanly, verified end-to-end in this planning session (100% coverage,
matching the existing `test:coverage:all` gate's own numbers, with every `SF:` line correctly
resolving to a real `src/*.ts` file). Task 1's script performs this rewrite.

**Existing action pins in this repo's own workflows** (`build.yml`, `publish.yml`,
`package-audit.yml`, all read in full during planning): `actions/checkout@v5`, `actions/setup-node@v6`,
plain `npm install` (never `npm ci`), no `cache:` key on `setup-node`, and `node-version: 26.x`
unquoted for the single-version jobs (`publish.yml`, `package-audit.yml`; `build.yml`'s matrix also
tops out at `26.x`). `/home/acolomba/pi-claude-marketplace`'s `sonarcloud.yml` (reference only) pins
`actions/checkout@v7` / `actions/setup-node@v7` and uses `npm ci` -- do NOT copy those; match this
repo's own pins and `npm install` convention instead.

**`test/documentation.test.ts` and `test/repositoryGovernance.test.ts`** (both read in full) are static
gates over `README.md`/`SECURITY.md`/issue templates via plain-text regex assertions. The one this plan
