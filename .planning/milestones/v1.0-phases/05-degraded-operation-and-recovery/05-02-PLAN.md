<objective>
Make a restart on cached state visibly stale before anything else, then build the marking pass that
makes it so, as one exported function the platform and the Cucumber harness both call.

Purpose: this is the highest-value item in the phase and the easiest to get a false green from. The
harness deliberately drops the restored service surface today, and its own docblock argues that is
"a stricter question than a real restart asks and never a laxer one." That was true for Phase 4's
question — did the plugin republish? — and is false for Phase 5's — does a stale value read as
trustworthy before it republishes? With no restored services there is nothing stale to read, so every
scenario in this plan would pass whether or not the plugin marks anything. That is the same shape as
the six positives Phase 4 produced that passed for the wrong reason: the fixture sitting at the value
the defect produces.
Output: a harness that carries services and values across a restart, the exported marking pass, both
call sites, and the scenarios that can now fail.
</objective>

## Planner assumptions carried by this plan

**PA-03 — extending the harness may invalidate an existing scenario.** Seventy-eight scenarios
currently run against a harness that restores no service surface, and some restart assertion may be
relying on that empty surface. `05-RESEARCH.md` A5 rates this medium. Task 1 runs the whole suite
immediately after the harness change and before any new scenario is written, and treats a failure as
information about that scenario rather than as breakage to route around.

**PA-04 (RES-04 concurrency, backstop) — Homebridge's own call ordering cannot be proven here.**
The claim that every `configureAccessory` call lands before `didFinishLaunching` is Homebridge
behaviour. The harness reproduces it, but a fixture reproducing an ordering is not evidence that the
real runtime honours it. The plan asserts the half it can — the pass runs synchronously inside
`configureAccessory`, and nothing downstream of `onTrustworthyInventory` can run before the runtime
starts — and records the other half as a backstop truth that a verifier must not silently pass.
