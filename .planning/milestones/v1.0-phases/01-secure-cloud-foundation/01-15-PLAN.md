<objective>
The malformed-email refusal quotes the configured account email verbatim into a log line, and it does so on the one path where nothing has been registered as a secret yet, so the redacting logger has nothing to substitute and none of its four credential patterns matches a bare email in prose. An account email is an account identifier, which PROJECT.md's Privacy constraint and CLAUDE.md both say cannot enter logs. No scenario covers that refusal at all, so nothing catches a regression.

Purpose: this is the phase's privacy gap. It is small in mechanism and it sits on the very first thing a misconfigured install does. Alongside it, the settings form and the validator genuinely disagree about blank strings and about whether the platform name is required, so the form can save a configuration the plugin then refuses to start on — which is precisely SC-1's promise inverted.

The comment in the platform constructor says the quoting was deliberate. That comment is not a project document and does not override a constraint that two project documents state; this plan resolves the conflict in favour of the constraint and records the reasoning, so the two do not sit contradicting each other any longer.

Two smaller defects in the same neighbourhood come with it, because they sit in the module the refusal is logged through: the fallback that describes an unserializable log parameter can itself raise out of the logger, and the registered-secret list is appended to forever, three values per credential rotation, so a bridge running for a month scans a growing array on every log line and holds every expired credential value in memory. The phase goal says trustworthy state over a long-running Homebridge lifecycle; a structure that degrades with uptime is that goal's own subject matter.

Output: a refusal that says what to fix without saying who you are, a form that accepts exactly what the runtime accepts, and a logger that cannot raise and does not grow.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `config.json` → Homebridge log | Operator-supplied account material crosses into a file operators share when they ask for help. |
| settings form → runtime validation | Two independent validators guard the same values, and a disagreement is a broken install. |
| arbitrary object → redacting logger | The logger is handed values it did not construct, from inside handlers that must not raise. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-82 | Information disclosure | account email quoted into the refusal line | high | mitigate | The refusal names the field and the rule and quotes no value, so nothing depends on the redacting logger having been told about a value it cannot have been told about yet. A scenario asserts the configured value appears in no logged line. |
| T-01-83 | Information disclosure | account identifier registered as a secret to work around the above | medium | mitigate | Rejected as the fix and recorded as rejected: it would place the raw identifier into the process-lifetime secret list and still leave a marker where a value was. |
| T-01-84 | Denial of service | form saves a configuration the runtime refuses | medium | mitigate | The required list and the non-blank rules on the three text fields are brought into line with the validator, with cases on both sides asserting the agreement. |
| T-01-85 | Denial of service | log call raising out of the logger | medium | mitigate | The unserializable fallback reads nothing off the value, so no object a caller can construct can make a log call raise from inside a catch block. |
| T-01-85a | Information disclosure | superseded credential material retained for the process lifetime | medium | mitigate | A rotated value is registered under a role and replaces its predecessor, so expired credential material is dropped rather than accumulated; values registered with no role are kept deliberately and are the two that must never stop being redacted. |
| T-01-85b | Denial of service | redaction cost growing without bound | medium | mitigate | The rotated-value count stays flat instead of growing by three an hour, so the per-log-line scan cost does not climb over a months-long run. |
| T-01-86 | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs no package, and in particular adds no schema validation library; the schema cases stay structural. |
</threat_model>
