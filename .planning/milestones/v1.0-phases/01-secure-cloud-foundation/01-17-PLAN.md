<objective>
The runtime has no state meaning that monitoring has stopped. After a refused credential — the one failure this project treats as final, after which no poll, no credential refresh, and no shadow will ever run again — the monitoring path reads as the degraded-but-working value, and the terminal branch records nothing in the failure log. Worse, the same exported type name carries two disjoint value sets: the runtime's producer and the declaration-only consumer shipped for the next phase share no member at all, so the field cannot be fed by the thing that produces it. Separately, a shutdown landing between the moment a shadow connection is opened and the moment it is recorded leaves a socket nothing will close.

Purpose: this is the composition seam, and it is where a shipped contract is wrong rather than merely incomplete. Nothing consumes the monitoring path in production yet, so today the false normal is latent — which is exactly why it is cheap to fix now and expensive to discover as a translation layer later.

Scope fence: this plan makes the state representable and the type single. It does **not** build the user-facing separation of a dead monitoring path from a degraded one; that is RES-04 in Phase 5 and the verifier deferred it there explicitly. It also does not touch the other declaration-only scaffolds under `src/device`, `src/accessories`, or `src/persistence`, and it neither adds nor removes an entry in the dead-code gate's ignore list.

Output: one monitoring-path type with a dead state the runtime actually reaches, a shutdown that closes what it opened and a unit case that proves it in the window where the race lives, and scenarios that ask the broker rather than trusting silence.

This plan is also where the gap-closure set records what it did **not** do. The deferral register below is part of the deliverable: the next verification pass reads it, and an unrecorded deferral reads as an unaddressed gap.
</objective>
