## Silence across a restart

Asked once, then re-asked after a premise was measured.

**First pass:**

| Option | Description | Selected |
|--------|-------------|----------|
| Restart resets the window | Silence measured within one process run only | |
| Persist a wall-clock anchor | Store last wall-clock arrival, pair with the monotonic delta | ✓ (first pass) |
| Decide during planning | Depends on whether anything persists shadow-arrival times | |

**Measurement that followed:** nothing persists shadow-arrival times today.
`AccessoryContext` carries `primaryPump`, `backupPump`, `watermarks` and `lastVendorName`;
no arrival timestamp exists anywhere in `src/`. So the anchor means a new persisted field.

**Tension surfaced:** with "silent until told otherwise" already covering the restart, an
anchor can only change the outcome in one direction — *suppressing* the silent reading for a
pump heard shortly before the restart. That is the branch a backwards wall-clock jump across
a restart would exploit, reintroducing IN-03's exact failure on the restart path.

**Second pass:**

| Option | Description | Selected |
|--------|-------------|----------|
| Drop it — restart resets | No new persisted field; the fallback carries the restart case | |
| Keep it, clamped | Persist the anchor but never let it shorten a window — sooner, never later | ✓ |
| Keep it as chosen | Accept the backwards-jump exposure on the restart path | |

**User's choice:** Keep it, clamped.
**Notes:** Adds a persisted field and a migration path for installs predating it, which fall
through to the silent-until-told-otherwise fallback.
