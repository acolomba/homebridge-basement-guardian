# Phase 05.1 Plan 04: Monotonic Silence Summary

**Shadow silence is now measured as the larger of a `process.hrtime.bigint()` elapsed time and a wall elapsed time, so a system clock set back an hour cannot shorten a window and hand a dead pump a fresh certificate of health.**

## Accomplishments

- `src/runtime/monotonicClock.ts` declares `MonotonicClock` and `systemMonotonicClock`, copying `clock.ts` line for line: the file-level docblock sits on the interface, `now()` names the unit and says the epoch is arbitrary, and the production instance carries "Wire this at the composition root only." `NANOSECONDS_PER_MILLISECOND` sits above it with the reason for its value, and the division happens on the `bigint` so the reading is an exact integer.
- The port is constructed in exactly one place, `src/platform.ts`, and threaded through `AccountRuntimeDeps` → `AccountRuntimeOptions` → `createMonitoringHealth` exactly as `clock` is threaded today.
- `monitoringHealth.ts` holds one `ShadowArrival` per device, read on both bases at the same instant, and `silenceElapsedMs` returns the larger of the two elapsed terms. The comment above it names what each term covers and names the rejected alternative, because the inversion is the defect.
- The unit suite's movable clock grew a second base with an origin unlike the first. `moveTo` moves both; `moveWallTo` moves the wall base alone. The seventeen cases beside the new ones keep meaning what they meant.
- The Cucumber World carries two bases with unrelated origins, `advanceClock` moves both, and `jumpWallClock` moves the wall base alone. A new step drives it, and a scenario shows a pump that stopped speaking staying untrusted across an hour-long backwards correction.
- No consumer of wall time was changed: `src/cloud/shadow.ts`, `src/cloud/auth.ts`, `src/device/state.ts`, `src/accessories/reconciliation.ts` and `src/runtime/failureLog.ts` are untouched by this plan.

## Recorded Limits

- **The suspend consequence is cited, not observed.** `CLOCK_MONOTONIC` not advancing across a system suspend is the documented Linux distinction from `CLOCK_BOOTTIME`, cited from `man 2 clock_gettime`. The research probe established which of the two `process.hrtime.bigint()` follows; it did not suspend a host and watch the divergence, because the host had no accumulated suspend time and there was nothing to observe. The code comment in `src/runtime/monotonicClock.ts` says this in the same words. What is pinned automatically is the arithmetic that answers a suspend, not the suspend itself.
- **No Node 24 result is claimed.** Node 24 is not installed on this host. Every measurement above ran on the default `node`. CI runs `[22.x, 24.x]` (`.github/workflows/build.yml:31`) and is where a 24.x result comes from.
- **No real multi-device evidence exists** (D-10). This plan's scenario is single-device, which is the right shape for a clock question, so the limit does not bite here — but it is unchanged.

## Decisions Made

- **One record, not two maps.** The plan asked for the wall reading in a second device-keyed map beside the arrival stamps. Measured: with two maps the anchor read is `number | undefined`, and the `undefined` arm cannot be reached through this module's API, because `admitDevice` and `recordShadowMessage` write both stamps at the same instant and `forgetDevice` drops both. Branch coverage is a real gate at 100, so an unreachable arm fails it. A single `ShadowArrival` record removes the arm instead of hiding dead code behind a guard, and it also makes the two stamps impossible to prune apart.
- **The wall term is never omitted in this plan**, because no path can produce a monotonic stamp without a wall one. The plan's "omitted when no anchor exists" shape belongs with plan 05.1-05's persisted anchor, which is the first thing that can supply one without the other. Recorded as a deviation below rather than built as a branch no case can take.
- **`isShadowSilent` keeps its `(lastMessageAt, now)` signature**, as the plan required. The caller names the intermediate — `silentSince`, the instant the longer of the two silences began, carried onto the base the threshold is measured on — so the round trip reads as a statement rather than as arithmetic noise.
- **The `||` form was rejected.** `max(a, b) >= T` is exactly `a >= T || b >= T`, so the clamp could have been two calls to `isShadowSilent` with no `Math.max` at all. It was not taken: the expression V8's mutation names would no longer exist, and two independent rules read as two policies rather than as one clamp with a direction.
- **The two origins are deliberately unrelated.** `MONOTONIC_START_TIME` is `4_000_000` against a wall `START_TIME` of `1_700_000_000_000`, and `SCENARIO_MONOTONIC_START_TIME` is `4_000_000` against a wall origin parsed from an ISO date. A base swap is then off by three orders of magnitude and fails loudly instead of agreeing by coincidence.
