## Deviations from Plan

### The recovery case needed more than following the constant

The plan says to keep both log-once cases passing untouched and to **stop** if either needs editing
beyond following the rewritten constant. One did, and the reason is not the one the stop-condition
guards against.

`reports the controller link condition again after a recovery and a later re-entry` drives lost →
recovered → lost. The recovery in the middle publishes every row, so the second transition's line
names fifteen services where the first named two. **The latch is intact** — two entries for two
transitions, which is what that case measures — and only the text of the second entry changed. The
case now asserts both renderings, which pins the latch and the derivation together rather than
weakening either. The plan's premise, that both cases would survive by referencing the constant, held
for one of the two.

### The empty-list sentence was removed rather than written

The plan requires an empty-list sentence and a case for it, calling the branch unreachable from
Cucumber but reachable from a unit case. It is reachable from neither. `System Self-Test` and
`Alarm Mute` set `alwaysPublish`; `isSuppressed` answers only for the seven removable notification
kinds, so neither Switch can be suppressed; both are filed under non-connectivity scopes that
tolerate nothing. Any accessory reaching that line therefore publishes at least those two and
withdraws both. The one path that publishes nothing is the unresolved-family branch, which sets
`controllerLinkLost: false`, calls `reportDegradation()` and never calls `reportControllerLink()`.

A branch nothing can reach is dead code that fails the 100 percent branch gate, so the ternary was
removed and the measurement written in its place.

### The twin-row mutation would have been a null result, so a case that discriminates was added

The plan predicts the kind-and-subtype join fails the case asserting both `backup-battery` names
appear. Against the implementation actually built it does not: membership is tested per catalogue row,
so a collapsed key still admits both rows and both names still render.

The plan allows reporting that as a null result. Instead the case that does discriminate was added:
a decoded battery group carrying only `voltageLow` projects a value for `Backup Battery Facts` and
none for `Backup Battery`, so exactly one of the two rows is published — and a collapsed key then
names the service the accessory never published, which is the over-naming threat T-05.1-19 exists
for. `LinkOverrides` grew a `battery` field to build it. The mutation fails that case and only that
case.
