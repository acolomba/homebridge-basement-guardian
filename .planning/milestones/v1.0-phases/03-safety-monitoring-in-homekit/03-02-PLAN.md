<objective>
Give the Gemini family adapter the two things the HomeKit tier needs from it: the explicit,
provisional water-level ladder that turns a legal vendor code into a percentage and a flood verdict,
and a per-field trust scope so one invalid field faults one scope instead of the whole device.

Purpose: `geminiFamily.validate()` is currently all-or-nothing — one out-of-domain field returns
`{ valid: false }` for the whole snapshot and the accessory degrades all five scopes together. That
contradicts phase success criterion 6 and locked `D-014`, both of which require faulting only the
narrowest owning scope. The data already exists (`FieldViolation` carries `{ field, reason }`); what
is new is the field-to-scope map and a `decode()` path that still returns usable state for the scopes
that did validate. The water ladder belongs here for the same reason: `src/device/family.ts` already
records that `water_level` is a thermometer code on one family and a plain ordinal on another, and
that the wrong decoder produces a plausible, wrong, safety-relevant reading — so the meaning stays
behind the family boundary.
Output: `src/device/waterLevel.ts`; a scope-aware `FieldViolation` and a `ScopedDomainState` contract
in `src/device/family.ts`; and a Gemini adapter that validates and decodes scope by scope.

Scope fence — D-10: `RES-01` is split, and this plan delivers only its field-validity half. What
belongs here is everything an invalid, out-of-domain, or omitted field implies: preserve the last
valid value, fault the narrowest owning scope, and never let a partial or invalid update clear an
active safety condition. What does NOT belong here is the time-based half — the roughly 898-second
device heartbeat, the two-missed-heartbeat staleness rule, and shadow silence as a secondary
staleness signal. Those are the next milestone phase's, alongside the monitoring-path work that
already scopes them, and building them now would mean building a staleness policy before the phase
that defines what it has to serve. Concretely: no module this plan writes takes a `Clock`, reads a
timestamp to judge freshness, counts elapsed intervals, or infers anything from the absence of a
message. `snapshot.receivedAt` is carried through as the `lastTrustedAt` bookkeeping the accessory
already keeps; it is never compared against a deadline.
</objective>
