<objective>
Close the three remaining accessory-side behaviours: a lost pump-controller link stops the plugin
trusting everything downstream of the controller while keeping the link adapter itself truthful, live
canonical state reaches HomeKit between polls, and the immediacy requirement is gated by four
independent falsifiable layers plus a negative control.

Purpose: `RES-02` requires `serial_communications === false` to activate `Pump Controller Link Lost`,
fault the controller-derived services, preserve their values, and expose when trustworthy controller
data last arrived. `SAFE-07` requires transitions to publish and clear immediately — and it forbids
something from *existing*, which observed behaviour alone cannot prove, because a debounce shorter
than whatever a harness advances would pass. `D-18` names the injected timer spy; research then
demonstrated that a `globalThis.setTimeout` spy does not see `node:timers/promises`, which is this
codebase's house style in three modules, so the gate needs four layers rather than one.

This plan also closes a gap found during planning that no source artifact records. The accessory's
`update()` is reached only from `registerDiscoveredDevices`, which runs once per successful REST poll;
`applyReportedPatch` updates the canonical store but reaches no accessory. With a default poll interval
of about fifteen minutes and pump runs lasting seven to fifteen seconds, `SAFE-03`'s "every live
backup-pump activation updates immediately" is not deliverable through the poll path alone. The store
already exposes `subscribe(deviceId, listener)` from the first milestone with no production consumer;
this plan wires it. The research architecture diagram assumes this connection already exists, which is
why the gap was not raised earlier.
Output: the `Timers` port, controller-link distrust, a snapshot-source discriminator, and a platform
that routes configuration and live state into the accessory.

Why this waits on the full catalogue: this plan reads rows that 03-05 writes. The controller-link
assertion — that every row except the link adapter stops publishing while the link is lost — only
discriminates when the four other fault adapters, both pumps, the water services, and the battery
pair exist to stay silent. Against the tracer's three rows it would pass while proving almost
nothing, and the same is true of the suppression assertion that `updatePlatformAccessories` fires
when `ignoredFaults` removes a service. The dependency is therefore semantic rather than
file-level: 03-05 and this plan share no file, so nothing would collide, but running this one first
would quietly weaken its own evidence.
</objective>
