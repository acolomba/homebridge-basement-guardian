## http2-idle-timeout-crash — uncaught `InformationalError: socket idle timeout` from an HTTP/2 stream on Node 26

- **Date:** 2026-09-05
- **Error patterns:** InformationalError, socket idle timeout, UND_ERR_INFO, onHttp2SessionIdleTimeout, ClientHttp2Stream, uncaught exception, HTTP/2, allowH2, undici, idle window, node 26
- **Root cause(s):** AND-gate of two conditions. (1) ENVIRONMENT: the run was on Node 26.8.1, whose bundled undici 8.10.0 flipped the `allowH2` default from `false` to `true`, so the same unmodified code negotiates a different wire protocol purely as a function of the Node major it runs on (verified on three real binaries: 22.21.1 -> HTTP/1.1, 24.13.0 -> HTTP/1.1, 26.8.1 -> h2); (2) CODE: both vendor `fetch()` call sites passed no dispatcher, so they implicitly inherited whatever the runtime's undocumented default was instead of stating the protocol the integration requires. On the h2 path undici arms a 4s session idle timer whose expiry destroys the pooled socket with exactly `InformationalError("socket idle timeout")`, and it guards a released-but-still-open h2 stream with only a one-shot `stream.once('error', noop)`, so a second error on that stream has no listener left and escapes as an uncaught top-level exception (upstream undici teardown race, nodejs/undici #5586 family — never locally reproduced, 0/5 attempts, and the fix does not depend on characterizing it).
- **Fix:** Route vendor HTTP through userland undici's own `fetch` + a shared `Agent({ allowH2: false })` end to end (`src/cloud/httpDispatcher.ts`), injected as an `httpFetch` port on `CloudApiOptions`, `AuthClientOptions`, and `AccountRuntimeDeps`, mirroring the existing `connect: MqttConnect` port, and wired at every composition root. The fetch and the Agent MUST come from the same undici copy: a userland Agent passed as `init.dispatcher` to the BUILT-IN global fetch is rejected on Node 22 and 24 with `invalid onRequestStart method`, because the built-in fetch's dispatch handler is shaped for its own bundled undici major. Also: `api.ts`'s `narrow()` now cancels an error response's body before throwing; `engines.node` widened to `^22.10.0 || ^24.0.0 || ^26.0.0`; `undici ^7.29.1` added (not `^8`, which would raise the Node floor to `^22.19.0` for no benefit); CI matrix gained `26.x`.
- **Files changed:** src/cloud/httpDispatcher.ts (new), src/cloud/api.ts, src/cloud/auth.ts, src/runtime/accountRuntime.ts, src/platform.ts, test/cloud/httpDispatcher.test.ts (new), test/cloud/alpnServer.ts (new), test/cloud/api.test.ts, test/cloud/auth.test.ts, test/platform.test.ts, test/runtime/accountRuntime.test.ts, test/packageManifest.test.ts, test/packaging/dependencyAllowlist.test.ts, test/packaging/dependencyTelemetry.test.ts, features/support/world.ts, features/real-pump/support/realWorld.ts, package.json, package-lock.json, .github/workflows/{build,publish,package-audit}.yml
- **Why not caught:** No gate existed for this class. Every unit test mocked `globalThis.fetch`, so no gate ever observed which protocol actually went out on the wire — the one thing that mattered. CI tested only 22.x and 24.x, both of which default to HTTP/1.1, so the defect was unreachable on every gated configuration and only appeared on a developer machine running an undeclared Node major. It also needed a real ~960s idle window, which only the opt-in live-account suite ever produces.
- **Recurrence guard:** Regression tests that assert the negotiated ALPN protocol over a real loopback h2-capable server with NO mocked fetch, exercising the real production code path — `test/cloud/api.test.ts:never negotiates HTTP/2 with the vendor, even when the server offers it`, its mirror `test/cloud/auth.test.ts:never negotiates HTTP/2 with the vendor tenant, even when the server offers it`, and `test/cloud/httpDispatcher.test.ts:negotiates HTTP/1.1 even when the server offers HTTP/2` (support module `test/cloud/alpnServer.ts`). Plus a config-default change: `.github/workflows/build.yml` now tests `26.x`, so the Node major that exposed this is gated from now on, and `test/packageManifest.test.ts` pins the widened `engines.node`.

**Transferable lessons:**

1. **A mocked boundary cannot catch a defect in what crosses that boundary.** 19 `t.mock.method(globalThis, 'fetch', ...)` sites gave 100% coverage of the call sites while proving nothing about the protocol negotiated. When the wire behavior IS the requirement, test against a real loopback server.
2. **Run the feasibility probe on every supported configuration, not just the failing one.** The first chosen fix (userland Agent as `init.dispatcher` on the built-in fetch) probed green on Node 26 and would have caused total loss of function on Node 22 and 24. Probing all three majors falsified it before it shipped.
3. **An implicit runtime default is a hidden dependency on the runtime's version.** `fetch()` with no dispatcher silently inherits whatever the bundled undici decided this major; state the requirement explicitly instead.
4. **`\b` treats `_` as a word character.** A word-boundary regex intended to de-noise a substring scan silently missed `SENTRY_DSN`; verify a boundary change against the real spellings it must still catch, or it weakens the gate it was meant to sharpen.
